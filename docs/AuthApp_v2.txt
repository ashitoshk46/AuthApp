Authentication System Design – v2
---------------------------------

Overview
--------
This document outlines the architecture and design for the authentication system (AuthApp) version 2. It merges all detailed sections from v1 and integrates improvements discussed, including PostgreSQL migration, DB connectivity before server start, environment strategy, and deployment notes.

Key Improvements in v2
----------------------
- Migration from SQLite to PostgreSQL for production environments.
- DB connectivity check before starting the server (fail fast principle).
- Robust environment handling for dev and prod using NODE_ENV normalization.
- Security hardening: CSRF, CORS allowlist, rate limiting, Argon2id password hashing.
- Deployment notes for Docker and Render with external DB access options.

Architecture
------------
**Backend**: Express.js, PostgreSQL (Render managed service), pg Pool, optional ORM (Knex/Prisma).
**Frontend**: React + Redux + Tailwind CSS (future integration).
**Deployment**: Docker + Render hosting with environment variable injection.

Environment Strategy
--------------------
- Use `.env` for local development and Docker Compose.
- Render uses injected environment variables (DATABASE_URL, NODE_ENV).
- Normalize NODE_ENV check: `(process.env.NODE_ENV || '').trim().toLowerCase() === 'production'`.
- For local dev: external DB URL with SSL mode required.
- For Render prod: internal DB URL via environment variable.

Startup Flow
------------
- Validate DB connection before starting Express server.
- If DB is unreachable, log error and exit process.
- Optional: Implement retry logic with exponential backoff for transient failures.

API Endpoints
-------------
- `/health` → App status.
- `/db-health` → DB connectivity check using pg Pool.
- Future endpoints:
    * `/register` → Local registration with email verification.
    * `/login` → Local login with MFA.
    * `/social/:provider` → Social login (Google, GitHub).
    * `/verify/email` → Email verification.
    * `/mfa/*` → MFA setup and verification.
    * `/session/refresh` → Token rotation.
    * `/logout` → Session invalidation.

Security Enhancements
---------------------
- Password hashing: Argon2id.
- HTTPS only, HSTS, secure cookies (httpOnly, SameSite=strict).
- CSRF protection for state-changing requests.
- CORS allowlist (no wildcards).
- Rate limiting: IP + account-based thresholds.
- SQL safety: Parameterized queries only.
- Secrets: Rotate keys, encrypt TOTP secrets, store OTPs hashed.
- Audit logs for authentication events.

Deployment Notes
----------------
- Dockerfile: No hardcoded env vars; rely on Render injection.
- Render.yaml: Define environment variables and service dependencies.
- External DB access for local dev: Enable external connections or use Neon/Supabase.
- SSL configuration for production DB connections.

Testing Strategy
----------------
- Unit tests: Password hashing, token validation.
- Integration tests: Full flows (register → verify → login → MFA).
- Negative tests: Wrong passwords, expired OTPs.
- Security tests: OWASP ZAP, fuzzing, load tests.
- Performance tests: k6 or autocannon for load testing.
